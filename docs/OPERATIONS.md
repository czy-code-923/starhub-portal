# 安全与运维

## 服务管理（0.10.2）

Linux 在 root 终端执行 `python3 /opt/starhub-portal/scripts/manage.py start`，启动本项目并启用 systemd / Docker 开机自启。`stop` 停止本项目容器并禁用本项目助手；`restart` 重启本项目；`logs` 输出最近 100 条应用与数据库日志。关闭 SSH 不影响服务。不要在更新、备份恢复过程中停止服务。不停止共享 Docker，不删除数据。自定义目录需同时修改脚本路径并加 `--root /你的目录`。Windows 助手按管理员登录启动，Docker Desktop 需由其自身设置启用登录启动。

- 数据库只在独立内部 Docker 网络中通信；无 PostgreSQL 公网映射。应用容器无 Docker socket、无特权、只读根文件系统、非 root 运行。宿主机助手是单独受限任务执行器。
- 密码使用 Argon2id（19 MiB、2 次、1 并行），并发哈希限制为 2；应用连接池上限 4。初始应用限制 256 MiB，PostgreSQL 512 MiB / shared_buffers=32 MiB，按真实监控调整，不允许全局 Docker prune 或清理其他服务。
- SMTP、星枢密钥、支付宝密钥使用每安装独立的 AES-GCM 主密钥加密；设置接口只返回是否配置和非秘密元数据。日志不打印请求体、Cookie、支付签名、完整订阅凭据或环境配置。
- 邀请码同时保存校验哈希及加密原文，授权管理员可反复查看；邮件验证 / 找回链接单次有效，令牌放 URL fragment 防止 HTTP 访问日志和 Referrer 泄漏。注册邮件排队失败可重试，不直接标记已验证。
- 默认不信任来自公网的 `X-Real-IP`。反代配置由你管理时必须覆盖该头，并在 `portal.env` 的 `TRUSTED_PROXIES` 显式填入可信反代 CIDR。内置网关只信任自己的网络，已有宝塔反代只信任自己的 Docker 网关地址。
- 有域名时使用可达 HTTPS，并保持 IP 应急入口可查询。修改域名不改变 Agent 地址或原控制面设置；本项目不接管星枢订阅网关。
- 支付回调仅使用支付宝公钥验证，订单绑定创建时的渠道版本；切换密钥不会令尚未完成的旧订单突然使用新渠道验证。旧渠道保留供核账。
- 个人收款码按实际到账人工核验，截图不自动开通；退款须在相应收款渠道人工核账完成。本版不会因为后台显示“退款”而假装资金已退回。正式运营前必须通过真实商户沙箱与小额闭环验收。
- 备份 `/opt/starhub-portal/portal.env`、`compose.env`、`installation.json` 和 PostgreSQL dump。主密钥丢失将无法恢复加密设置；备份目录同样需要管理员权限，不能放进网站目录或 GitHub。
- 更新期间暂停本站写入，保留旧程序和数据库快照。中断恢复使用 `recovery.json`，助手启动时先完成恢复；恢复失败停止反复覆盖，检查本机日志处理。
- 账户停用到代理权限撤销有同步延迟；关注任务状态与 Agent 在线情况。控制面不可达时拒绝新的商业开通，而不是跳过校验。

本项目的自动化验证覆盖代码中已列出的场景，不等于已完成渗透测试、财务审计或大规模压测。后续优先项：完整退款工作流、服务账号 API、套餐变更折算、邮件投递监控、真实多客户端 / Windows 安装验收。

0.4.0 容量边界：当前星枢实现最多 500 个代理身份，是控制面和 Agent 的约束，不是承诺支持 500 人同时在线。每个独立订单消耗一个身份，历史停用身份也计入，原自用身份同样占用容量。注册人数与独立服务数不能混算。下单会检查控制面剩余身份，并扣除待付/待开通订单的预占，控制面还会进行最终校验。几十至数百购买用户的实际承载仍取决于订单数、节点回传、CPU、内存和磁盘；扩容前先压测，不直接取消边界。

应用保持 256 MiB 上限并设置 Go GOMEMLIMIT=192 MiB；数据库 512 MiB、最多 30 个连接，应用池 4 个连接。每页 25 条服务，只获取选中服务实时状态，二维码按需生成，隐藏页面停止刷新。助手每分钟仅采样本项目两个容器和安装盘，不运行全局清理、不收集其他容器详情。版本页可检查当前资源；GOMEMLIMIT 是 Go 软目标，不能替代容器硬上限。

旧合并权益迁移前由更新助手备份数据库。购买端冻结请求，星枢单事务写入全部新身份、撤销旧身份及链接；网络中断后用相同请求重试，不能手动删除迁移账本或重建用户。迁移成功后客户端须更新链接，离线 Agent 的撤权须等待重连和配置同步。保持付款记录，遇到错误先查询 migrate 任务及主管理员诊断接口。

同机兼容更新只读取 root 所有且权限受限的 `/etc/harbor/control.env`，令牌只发往固定回环地址，禁止代理和跳转；通过现有星枢官方更新器请求兼容版本，不执行来自浏览器的任意命令。外部星枢不会由此功能自动更新。
# 0.3.0 运营扩展

红包口令与 Telegram Bot Token 都由本安装独立 AES 主密钥加密，列表和审计不记录明文。主管理员管理机器人与授权数字用户 ID；普通通知不携带完整红包口令，口令私聊查询需明确授予 payments 和 redpacket 两项权限。私聊账号仍须妥善保护，已发出的消息无法通过本系统撤销。

Telegram 默认只通知，可复用已有机器人而不消费更新。独立命令模式需专用机器人，拒绝已有 Webhook；跨进程使用 PostgreSQL 会话锁，只保留一个消费者，未配置时不长期占用数据库连接。发送失败按接收人确认、退避重试，十次失败可由主管理员重试；已发送/失败队列保留 30 天。Telegram 在服务器已收到消息但网络响应丢失时可能出现重复消息，核款不得仅依据通知。

域名证书就绪只代表证书签发成功，不代表已有网站反代。本站与星枢同机时通过本机受限环境访问控制面 API，复用对应证书并创建回源本购买面板端口的反代；不会导出私钥、覆盖其他上游或控制面/订阅域名。域名任务须验证 `/portal/v1/health` 的安装 ID。清空域名时只停用本站标记的反代并保留证书。IP 入口与首选域名单独记录，修改域名不影响管理员通过安装端口恢复访问。
